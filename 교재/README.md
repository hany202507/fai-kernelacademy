# 강의자료 작성 규칙

updated: 2026-08-30 · 저자: 박상정 외

이 저장소는 **과정별 강의자료를 모으는 자리**입니다. 처음 자료를 올리기 전에 이 문서를 끝까지 읽어 주십시오.
1절과 3절은 예외가 없습니다.

---

## 1. 과정 하나가 내는 것 — 4종

| # | 파일 | 무엇 | 만드는 도구 |
|---|---|---|---|
| — | `README.md` | 과정 한 장 요약 (목표·대상·시수·상태) | 직접 작성 |
| 1 | `01_설명.html` + `.pdf` | 과정과 슬라이드를 설명하는 리포트 | `kernel-html-reports` |
| 2 | `02_슬라이드.html` | 강의용 슬라이드 | `kernel-html-slides` |
| 3 | `03_실습데이터/` | 입력·오류시나리오·기대결과 | 직접 작성 |

**리포트가 중심입니다.** 위원은 강의를 듣지 않고 검토합니다. 슬라이드만 보면 화면에 뜬 글자는 알지만
그 자리에서 무엇을 말하는지는 알 수 없습니다. 리포트가 그 자리를 메웁니다.

---

## 2. 폴더와 파일 이름

```
교재/
  README.md              ← 지금 이 문서
  _양식/                  ← 새 과정을 시작할 때 복사해 가는 골격
  <과정명>/
    README.md
    01_설명.html
    01_설명.pdf
    01_설명_원고.md        ← 리포트를 만든 입력 원고. 함께 올립니다
    02_슬라이드.html
    02_슬라이드구성.md      ← 슬라이드를 만든 입력 원고. 함께 올립니다
    03_실습데이터/
      README.md
      입력/
      오류시나리오.md
      기대결과/
```

**HTML 만 올리지 마십시오.** 입력 원고(`_원고.md`·`구성.md`)를 함께 올려야 다음 사람이 고칠 수 있습니다.
HTML 은 산출물이고, 고치는 대상은 원고입니다.

| 대상 | 규칙 |
|---|---|
| 파일 이름 | `번호두자리_이름.확장자`. 공백 대신 `_` |
| 버전 | `v0.x` 초안 · `v1.0` 위원 검토 통과본. 파일명에 붙일 때는 `_v0.3` |
| 날짜 | 문서 첫 줄에 `updated: YYYY-MM-DD`. 고칠 때마다 갱신 |
| 과정 폴더 이름 | 한국어 과정명 그대로 (예: `T1_기장트랙`, `AI활용입문`) |

## 3. 올리기 전에 — 예외 없는 네 가지

### 3-1. 실데이터를 반입하지 않습니다

이 저장소는 공개돼 있고, git 은 지운 파일도 이력에 남깁니다.
삭제 커밋을 올려도 이전 커밋을 되짚으면 그대로 보입니다.
상호·사업자등록번호·주민등록번호·계좌번호·실제 원장과 전표·실제 금액이 담긴 재무제표는
**어떤 형태로도 올리지 않습니다.** docx·xlsx·pdf 안에 든 것도 마찬가지입니다.

전체 목록과 자동 검사 훅 활성화 방법은 [CONTRIBUTING.md §1](../CONTRIBUTING.md) 을 보십시오.
클론마다 한 번 켜야 작동합니다.

```bash
git config core.hooksPath .githooks
```

**이미 올렸다면 되돌리려 하지 말고 즉시 박상정에게 알려 주십시오.**

### 3-2. 내용은 canon 을 먼저 고칩니다

[`canon/`](../canon/README.md) 이 정본입니다. 슬라이드·리포트는 canon 에서 렌더링된 파생물입니다.

슬라이드에만 고치면 **다음 렌더링에서 그 수정이 사라집니다.** 순서는 항상 canon → 자료입니다.
그래서 리포트의 슬라이드별 표에 `canon 근거` 열이 있습니다. 근거를 못 적는 슬라이드는
canon 에 그 내용이 없다는 뜻이므로, 자료를 쓰기 전에 canon 부터 채웁니다.

### 3-3. 실습 회사는 메종블룸 하나입니다

[`canon/10_예시실습/회사프로필.md`](../canon/10_예시실습/회사프로필.md) 의 (주)메종블룸이 정본입니다.
새 실습이 필요하면 메종블룸을 확장하십시오. 가상 회사를 새로 만들면 데이터셋이 갈라지고,
갈라진 데이터셋은 아무도 쓰지 않습니다.

### 3-4. 쓸 수 없는 단어가 있습니다

민간자격 등록증 발급 전까지 자격기본법 §39 에 따라 **「자격·인증·검정·공인」을 쓸 수 없습니다.**
대외로 나가는 모든 자료에 적용됩니다.

| 쓰지 않음 | 대신 |
|---|---|
| 자격 | 교육과정 |
| 인증 | 수료 |
| 검정 | 평가 |
| 공인 강사 | 파트너 강사 |
| 공인 교육기관 | 사용 등록 기관 |

예외는 직업명(`공인회계사`)·기관명(`한국공인회계사회`)·법률명(`자격기본법`)뿐입니다.
제품명 `Gridie` 도 이 자료에 넣지 않습니다.

## 4. 만드는 법 — 스킬로 만듭니다

저자마다 색과 여백을 새로 고르지 않도록 디자인을 템플릿에 박아 두었습니다.

**설치할 것이 없습니다.** 이 저장소의 `.claude/skills/` 에 두 스킬이 들어 있어,
저장소 폴더에서 Claude Code 를 띄우면 그대로 뜹니다. `/` 목록에서 확인하십시오.

| 스킬 | 만드는 것 |
|---|---|
| `kernel-html-slides` | 대본·구성안 → 1280×720 단일 파일 HTML 슬라이드 |
| `kernel-html-reports` | 원고·데이터 → 읽는 A4 보고서 HTML + PDF |

접두사도 명령어도 없습니다. 원고를 주고 말로 시키면 뜹니다.

```
02_슬라이드구성.md 로 슬라이드 만들어줘
01_설명_원고.md 를 A4 보고서로 정리해줘
```

**넘침은 눈으로 판정하지 마십시오.** 슬라이드 캔버스는 `overflow:hidden` 이라 넘친 줄이 그냥 사라집니다.
한 줄이 잘려도 화면은 멀쩡해 보입니다. 실측기로 재고 올립니다.

```bash
cd .claude/skills/kernel-html-slides/assets
pwsh -File slidecheck.ps1 "/절대/경로/슬라이드.html"
```

PowerShell 과 Chrome(또는 Edge)이 필요합니다. Windows 는 PowerShell 이 기본 탑재입니다.
보고서 쪽은 `kernel-html-reports/assets/printcheck.ps1` 이 A4 페이지 수·채움률을 재고 PDF 를 함께 뽑습니다.

스킬을 고치고 싶으면 이 저장소가 아니라 [이슈](https://github.com/hany202507/kernelacademy-web/issues)로 남겨 주십시오 —
여기 있는 것은 사본이고, 정본은 다른 곳에서 관리됩니다.

## 5. 산출물별 규칙

### 5-1. 설명 리포트 — 5개 장

| # | 장 | 담을 것 |
|---|---|---|
| 1 | 교육목표 | 대상·선수지식·시수·끝났을 때 할 수 있게 되는 일 |
| 2 | 목차 및 주요내용 요약 | 세션·부 단위 요약 + **canon 매핑** |
| 3 | 슬라이드별 내용 | 아래 표 형식 |
| 4 | 실습과 기대결과 | 입력 / 심어둔 오류 / 기대결과 / 채점 방법 |
| 5 | **검토 질문** | 3~5건 + 렌즈 표기 |

3장의 표는 이 네 열을 유지합니다.

| 번호 | 제목 | 이 자리에서 말하는 것 | canon 근거 |
|---|---|---|---|
| `T1-12` | 슬라이드 제목 | 3~5문장 | `canon/00_프레임워크/blocks/V-검증.md` |

**5장을 비우지 마십시오.** 검토자는 시간을 내어 봐 주는 사람입니다. 「봐 주십시오」만으로는 회신이 오지 않습니다 — 질문이 박혀 있어야 옵니다.
렌즈는 셋 중 하나를 적습니다 — **실무 정합성 / 데이터·기술 / 교육설계·거버넌스**.

### 5-2. 슬라이드

| 규칙 | |
|---|---|
| 번호 | `<과정코드>-<장번호>` 고정. 예: `T1-12` |
| 한 장의 요점 | **2~4개.** 넘으면 폰트를 줄이지 말고 장을 나눕니다 |
| 뼈대 | 표지 → 목차 → (구분 → 본문 여러 장) → 마무리 |
| 이모지 | 쓰지 않습니다 |

**번호는 반드시 고정하십시오.** 회신은 대개 이 저장소 밖에서 옵니다(문서·메일). HTML 에는 코멘트를 달 수 없습니다.
`T1-12` 가 찍혀 있어야 메일·메신저로도 그 장을 지목할 수 있습니다.

### 5-3. 실습데이터 — 세 칸

```
03_실습데이터/
  입력/           수강생에게 주는 파일 (은행거래·카드승인·세금계산서·급여대장)
  오류시나리오.md  심어둔 오류 목록과 그 의도
  기대결과/        사람이 확정한 정답
```

**기대결과가 없으면 실습이 아닙니다.** 골든셋은 `같은 입력 + 사람이 확정한 기대결과` 쌍이어야 성립합니다.
전기 확정 결산은 분석적 검토의 비교기준이지 당기 산출물의 정답표가 아닙니다
(2026-08-07 검토의견 §1).

`기대결과/` 는 검토·채점용입니다. **수강생 배포본을 만들 때 이 폴더를 뺍니다.**

실습 산출물 규격 3종(재실행 가능한 스크립트 · 산출 파일 · 검증 결과)은
[CONTRIBUTING.md §2](../CONTRIBUTING.md) 를 따릅니다.

## 6. 문체

정본은 스킬 안의 `kernel-html-slides/assets/tone.md` 입니다. 제목·소제목·콜아웃을 쓰기 전에 봅니다.

- 1인칭 격식 한국어(~습니다). 교육자·전문가 관점
- **근거 먼저, 결론 나중.** 자기평가성 강조어를 쓰지 않습니다
- 숫자에는 출처와 확인일을 함께 남깁니다. 교차검증이 안 되면 「미검증」으로 표시하고 대외 자료에 쓰지 않습니다
- 비유·대구·격언을 쓰지 않습니다
- 「전 세계에 없음」·「1원 오차 없음」 같은 단정은 조사 시점과 범위를 병기하는 형태로 바꿉니다

## 7. 올리기 전 체크리스트

- [ ] `git config core.hooksPath .githooks` 를 이 클론에서 실행했다
- [ ] 실데이터가 없다 — 첨부한 docx·xlsx·pdf 안까지 열어서 확인했다
- [ ] 내용을 canon 에 먼저 반영했다
- [ ] 슬라이드별 표의 `canon 근거` 열이 전부 채워져 있다
- [ ] 「자격·인증·검정·공인」·`Gridie` 가 없다
- [ ] 슬라이드에 고정 번호가 붙어 있다
- [ ] `slidecheck.ps1` 로 넘침을 쟀다
- [ ] 리포트 5장에 검토 질문이 3건 이상 있고 렌즈가 적혀 있다
- [ ] HTML 과 함께 입력 원고(`.md`)를 올린다
- [ ] 각 문서 첫 줄 `updated:` 를 갱신했다
