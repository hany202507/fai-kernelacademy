# 원리 · 왜 재무AI 교육은 다른가

## 1. 3문제, 재무 AI는 그냥 하면 되는 게 아니다

| # | 문제 | 이 교육의 답 |
|---|---|---|
| ① | **데이터 접근의 벽**, 회사 자료로 AI를 연습할 수 없다 (보안) | 가상 회사 「(주)메종블룸」([프로필](../10_예시실습/회사프로필.md)) 데이터 키트 = 실전 같은 연습장 |
| ② | **연습장의 부재**, 실무×데이터×AI를 미리 훈련할 환경이 없다 | 실습·훈련 70%, 드릴(변형 반복)과 실무 적용 미션 |
| ③ | **검증 없는 활용의 리스크**, 재무의 본질은 검토·통제 | V(검증) 독립 블록, 모든 실습 = [AI 수행→사람 검증→반영] |

## 2. 성장 = 교육 + 훈련

"알려주고 실행은 알아서"가 아니다. 훈련해서 실무에 붙는 것이 존재 이유.

- 교육(알게 한다): 강의·시연·프레임워크 → 지식체크
- 훈련(하게 만든다): 드릴 · 실무 적용 미션(수강생의 책상에서) · 피드백 루프(적용 리뷰) · 30일 팔로업
- 1회 따라하기는 실습이지 훈련이 아니다. 조건을 바꿔 반복해야 훈련이다.

## 3. 4D와 블록 문법의 매핑

Anthropic AI Fluency의 4D(글로벌 표준)를 재무 실무 절차로 구체화한 것이 6블록이다.

| 4D | 뜻 | 블록 문법에서 |
|---|---|---|
| Delegation | 무엇을 맡길까 | 업무의 블록 분해·워크플로 설계 |
| Description | 어떻게 시킬까 | 블록별 표준 지시서 |
| Discernment | 어떻게 판별할까 | **V 검증 블록** (tie-out·대사·재계산으로 구체화) |
| Diligence | 어떻게 책임질까 | **J 판단 블록**(사람 위임 불가) + 보안 게이트·실행환경 결정 |

Description–Discernment 루프 = "한 번에 완벽한 프롬프트가 아니라 **수렴하는 루프**". 골든셋(정답표) 채점 → 실패를 규칙으로 승격 → 재실행이 루프의 재무판.

## 4. 포지셔닝 문장

**"글로벌 표준을 한국 재무 실무의 언어로 옮기고,
AI가 낸 결과를 확인하는 데까지 잇는 과정."**

한 줄로 줄이면, **세계의 표준을 한국의 실무로, 그리고 확인까지.**

### 왜 「없는 것」에 걸지 않는가

이전 문장은 *"세계 어느 과정에도 없는 결산·검증·연동 실무를 얹은 과정"*이었다.
2026-08-28 클로드 아카데미를 전수 확인하면서 그 셋이 더는 빈칸이 아님을 알았다.

| 없다고 했던 것 | 지금 있는 것 (2026-08-28) |
|---|---|
| 결산 실무 | 재무 사용 사례 18건, 회사 간 분개 대사, 계정 조정, 계약서→원장 추출 |
| 연동 | NetSuite·Workday·S&P·Microsoft 365 커넥터 |
| 검증 | Finance 플러그인 `/reconciliation` `/sox-testing` `/audit-support` |

**빈칸은 메워진다.** 없는 것에 포지션을 걸면 벤더가 채울 때마다 다시 써야 한다.
그래서 축을 옮긴다. 없는 것을 하는 과정이 아니라, **나온 것을 소화해 잇는 과정**이다.
도구 쪽이 무엇을 더 내놓아도 이 문장은 유지된다. 소화할 대상이 늘어날 뿐이다.

### 무엇을 소화하고 무엇을 잇는가

| | 하는 일 | 도구가 멈추는 지점 |
|---|---|---|
| **번역** | 한국 제도의 언어로 옮긴다 | 나온 것은 ASC 606·SOX 기준이다 |
| **연결** | 국내 시스템에 붙인다 | 커넥터가 NetSuite·Workday에 머문다 |
| **기록** | 판단의 근거를 남긴다 | 예외를 표시해 넘기는 데서 끝난다 |
| **확인** | 산출물이 맞는지 본다 | 대사와 표본 선정까지 AI가 한다 |

마지막 줄이 V블록의 정의를 바꾼다. AI가 감리를 하게 되면 **그 감리를 확인하는 일**이 남는다.
자세한 것은 [V 검증](blocks/V-검증.md).
