# D 산출 블록

updated: 2026-08-12 · renders: 책 2부 / T2 S4 / YT "시산표에서 경영진 대시보드까지 10분"

## 정의
보고서와 신고서, 대시보드, 파일링, 아카이브. 결과를 **받는 사람에게 맞는 형태로** 내보내는 단계다.

## 역할 분담
- **AI**: 초안·대시보드·요약문 생성, 형식 변환
- **사람**: **메시지의 결정과 책임.** 무엇을 강조하고 무엇을 뺄지 정한다. 최종 발신자는 사람이다

## 핵심 규칙
1. **V 통과 전 산출 금지**, 수치 대사를 마치지 않은 대시보드·보고서는 배포하지 않는다.
2. **수신자별 정보 수준**, 경영진(요약·시사점) / 실무(내역·근거) / 외부·신고(법정 서식). 같은 데이터, 다른 렌더링.
3. **실행환경 태그 필수** ([runtime.md](../runtime.md)), 로컬 아티팩트인가, 클라우드 상시 배포인가. 민감도가 거부권.
4. 대시보드는 v1→v3 반복으로, 첫 생성물은 초안, 지표 추가·필터 요구·대사를 거쳐 확정 (Description–Discernment 루프의 응용).
5. 아카이브까지가 산출, 산출물·근거·판단 로그를 볼트에 남겨야 다음 기수(월·분기)가 이어진다.

## 표준 지시서 골격
```
[데이터] ~(V 통과본). [수신자] ~. [형식] 대시보드/보고서/신고 서식
[요구] ① 핵심 지표·구성 명시 ② 수치는 원본 값 그대로(재계산 금지)
③ 요약문은 사실과 해석을 구분 표기
[환경] 이 산출물의 실행환경 태그: [로컬/클라우드/하이브리드]
```

## 검증 체크 (V 연결)
- [ ] 대시보드·보고서 수치 = V 통과본 수치 (전수 대사)
- [ ] 민감 정보가 수신자 등급에 맞는가 (경영진 배포본에 개인정보 없음 등)
- [ ] 실행환경 태그와 실제 배포 위치 일치

## 실패 사례
- 미검증 초안이 그대로 경영진 보고 → 회의 중 숫자 정정
- 상세 원장 포함 파일을 클라우드 공유 → 민감정보 노출

## 도구·환경 (빠름층)
대시보드(아티팩트·스프레드시트·BI), 문서 생성. 배포 환경 결정이 이 블록의 절반 `[결정축 4개 적용]`
