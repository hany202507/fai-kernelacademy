# J 판단 블록

updated: 2026-08-12 · renders: 책 2부 (윤리·책임의 장) / T2 S4 / YT "AI가 대신 못 하는 단 하나"

## 정의
기준의 적용과 예외의 결정. 공제와 불공제, 계정분류, 충당 설정, 집행 우선순위가 여기서 갈린다. **재무 업무의 책임이 모이는 단계다.**

## 역할 분담
- **AI**: 판단 **후보**와 각 후보의 근거·리스크 제시. 양쪽 논거를 나란히 놓는다
- **사람**: **결정. AI에 맡길 수 없다.** 회계사의 직업적 회의주의가 필요한 부분이다

## 핵심 규칙
1. **AI의 결론을 결정으로 승격하지 않는다**. "AI가 공제라고 했다"는 근거가 아니다. 근거는 R블록의 원문이다.
2. **판단 로그를 남긴다**. 무엇을·왜·어떤 근거로·어떤 대안을 기각했는지. 이 로그가 세컨드브레인에 쌓여 **전기 판단의 승계** 자산이 된다.
3. 판단의 일관성, 같은 사안은 같은 결론 (전기 판단 로그와 대조). 바꾸면 변경 사유를 기록.
4. AI에게 시킬 것은 "결정"이 아니라 **"결정을 잘하게 돕는 것"**: 논점 정리, 반대 논거 생성(devil's advocate), 전기 판단 검색.

## 표준 지시서 골격
```
[사안] ~. [요구] ① 가능한 판단 대안을 모두 제시 ② 각 대안의 근거(조문·기준)와 리스크
③ 전기 유사 판단 검색(볼트) ④ 반대 논거 1개 이상
[금지] 단일 결론 단정 금지. 결정은 내가 한다.
[산출] 판단 대안 비교표 → (사람 결정 후) 판단 로그 초안
```

## 판단 로그 양식 (세컨드브레인 축적)
`사안 / 결정 / 근거(원문 링크) / 기각한 대안과 이유 / 결정자·일자 / 차기 참조 조건`

## 검증 체크 (V 연결)
- [ ] 결정에 원문 근거가 붙어 있는가 (AI 의견만으로 결정된 건 없는가)
- [ ] 전기 동일 사안과 결론이 일치하는가 (불일치 시 사유 기록 존재)
- [ ] 판단 로그가 작성됐는가

## 실패 사례
- AI 추천을 그대로 수용 → 감사에서 "판단 근거" 답변 불가
- 판단 무기록 → 다음 분기 같은 고민 반복, 담당자 교체 시 판단 유실

## 도구·환경 (빠름층)
판단 로그는 볼트(세컨드브레인)에. 민감 사안 다수 → 로컬 우선 `[로컬]`
