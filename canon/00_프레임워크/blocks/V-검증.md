# V 검증 블록 ★서명 블록

updated: 2026-08-12 · renders: 책 2부 핵심장 / T2 S3 / YT "AI 산출물을 감리하는 법"

## 정의
AI가 낸 결과를 **감리(監理)하는** 단계. 대사와 tie-out, 재계산, 근거 확인이 들어간다(DB-02 공백②). 확인하지 않고 쓰면 오류가 그대로 반복된다.

## 역할 분담
- **AI**: 검증의 **실행.** 자동 대사, 체크리스트 순회, 차이 내역 산출
- **사람**: 검증의 **설계와 최종 승인.** 무엇을 어떤 방법으로 검증할지, 통과 기준은 무엇인지 정한다

## 검증 방법 카탈로그 (재무 절차의 번역)
| 방법 | 내용 | 적용 |
|---|---|---|
| **양방향 대사** | 합계·건수를 원본↔산출물 양방향 대조 | C·P 산출 전반 |
| **tie-out** | 재무제표↔시산표↔원장의 연결 일치 | 결산 |
| **독립 재계산** | 같은 값을 다른 경로(수식·표본 손계산)로 재산출 | 세액·상각 등 계산 |
| **골든셋 채점** | 확정된 전기 결과를 정답표로 신규 산출물 채점 | 루프 개선의 엔진 |
| **분석적 검토** | 전기 대비·비율·추세로 이상 탐지 | 결산·보고 |
| **근거 원문 확인** | 인용 조문·기준의 원문 대조 | R·J 산출 |

## 핵심 규칙
1. **검증도 AI에게 시키되, 만든 AI와 검증 세션을 분리한다** (자기 채점 금지, 독립성).
2. 검증 결과는 [통과/차이내역/보류] 3분류로, "대체로 맞음"은 검증이 아니다.
3. 차이는 원인 규명 후 종결, 차이의 원인이 규칙 결함이면 P블록 지시서로 승격(루프).
4. 검증 체크리스트 자체가 산출물이다. 블록 라이브러리에 축적, 팀 표준화.

## 표준 지시서 골격
```
[대상] ~산출물. [원본] ~. [방법] (카탈로그에서 선택 명시)
[요구] ① 항목별 [통과/차이/보류] 판정 ② 차이는 건별 내역·금액 ③ 판정 불가는 사유
[산출] 검증 요약(통과율) + 차이 내역표 + 후속 조치 제안
```

## 실패 사례
- 만든 세션에서 "검토해줘" → 자기 산출물 옹호 (독립성 상실)
- 합계만 대사 → 상계된 오류 미탐지 (건수·구성까지)

## 도구·환경 (빠름층)
수식·스크립트 기반 자동 대사 우선. 원본 데이터 위치 따라 환경 결정 `[원본과 같은 환경]`
