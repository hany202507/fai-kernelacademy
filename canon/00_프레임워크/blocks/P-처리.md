# P 처리 블록

updated: 2026-08-12 · renders: 책 2부 / T2 S3 / YT "분개 500건을 5분에: 규칙이 전부다"

## 정의
분류와 계산, 집계와 생성. AI가 가장 잘하는 **대량 반복 처리**다. 다만 품질은 처리 규칙이 얼마나 분명한가에 달려 있다.

## 역할 분담
- **AI**: 대량 분류·초안 생성·집계
- **사람**: **처리 규칙의 정의.** 분류 기준과 예외 처리, 출력 형식을 글로 남긴다

## 핵심 규칙
1. **결정적 계산은 코드·수식으로**, 합계·세액·상각 같은 계산을 LLM의 암산에 맡기지 않는다(1원 오차 불허). LLM은 규칙 적용·분류·생성, 계산은 수식·스크립트.
2. 규칙은 지시서에 명문화, "적절히 분류하라"는 지시가 아니라 실패 원인이다. 기준·우선순위·예외를 열거.
3. 모호 케이스는 **J(판단)로 넘겨라**, AI가 임의 결정하지 않도록 "애매하면 [보류] 표기" 지시.
4. 규칙은 골든셋 채점으로 진화한다 (오분류 → 규칙 승격, [principles.md](../principles.md) 루프).

## 표준 지시서 골격
```
[입력] ~데이터. [규칙] ① 분류 기준(열거) ② 우선순위 ③ 예외 처리
[모호] 확신 없으면 [보류]로 표기하고 사유 기재 (임의 분류 금지)
[계산] 금액 계산은 수식/코드로 수행하고 산식을 남겨라.
[출력] 형식 지정 + 처리 건수·보류 건수 요약
```

## 검증 체크 (V 연결)
- [ ] 표본 재계산 (무작위 n건 손계산 대조)
- [ ] 입력 합계 = 출력 합계 (건수·금액)
- [ ] 보류 건이 실제로 모호 케이스인가 (과소·과다 보류 점검)

## 실패 사례
- 흐릿한 규칙 → 같은 거래가 실행마다 다른 계정으로 (비결정성)
- LLM 암산 → 마지막 자리 오차 / 보류 없이 전건 분류 → 조용한 오분류

## 도구·환경 (빠름층)
스프레드시트+AI, 코드 실행 도구. 원장급 데이터는 로컬 우선 `[민감도 따라]`
