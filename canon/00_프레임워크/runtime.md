# 실행환경(런타임) · 어디서 돌릴 것인가

updated: 2026-07-26 · renders: 책 2부 보론 / T2 S1·S4·S6 / T1 L1 일부 / YT "로컬이냐 클라우드냐" 편

블록으로 워크플로를 조립했으면 **어디서 실행할지**를 정해야 실무에 안착한다. 모든 모듈은 3층으로 완성된다: **무엇을(블록) × 어디서(런타임) × 무엇으로(도구).**

## 3환경

| 환경 | 특징 | 한계 | 대표 도구·방법 |
|---|---|---|---|
| **로컬** (내 PC) | 데이터 반출 없음(최고 보안), 오프라인, 개인 소유 | 나만 사용, PC 켜져야 실행, 유지보수 내 몫 | 엑셀, Claude Desktop+로컬 MCP, 옵시디언 볼트, 로컬 스크립트 |
| **클라우드** (외부 서버) | 협업·공유, 상시 가동(무인 자동화), 어디서나 접근 | **데이터 반출 = 보안 검토 필수**, 구독 비용, 벤더 종속 | 웹 대시보드, SaaS, 클라우드 스케줄러·자동화 |
| **하이브리드** | 민감 처리=로컬 / 공유·상시=클라우드 | 설계 복잡도 | 로컬 전처리(마스킹·집계) → 클라우드 게시 |

## 4결정축

1. **데이터 민감도**, 데이터 등급표에서 이 산출물의 최고 등급은? (급여·주민번호 → 로컬 우선)
2. **협업·공유**, 나 혼자 보나, 팀·경영진이 보나? (공유 필요 → 클라우드로 기울음)
3. **상시성**, 사람이 실행하나, 스케줄로 무인 실행되나? (무인 자동화 → 클라우드/서버)
4. **비용·유지 역량**, 구독료와 관리 부담을 감당할 주체가 있나?

**결정 순서: 민감도가 거부권을 가진다.** 협업·상시성이 아무리 필요해도 민감도가 허용하지 않으면 하이브리드(마스킹·집계 후 게시)로 우회한다.

## 핵심 연결

- **런타임 선택 = C블록 보안 게이트의 연장.** "어디서 돌리느냐"가 "데이터가 어디로 가느냐"를 결정한다.
- 모든 산출물에 **실행환경 태그**를 붙인다: `[로컬]` `[클라우드]` `[하이브리드: 로컬처리→클라우드게시]`
- 조직 단위에서는 S6의 AUP(AI 사용 정책)에 "승인 실행환경 목록"으로 명문화된다.

## 대표 사례 (교육용)

| 사례 | 결정 | 이유 |
|---|---|---|
| 급여대장 검증 | 로컬 | 주민번호·급여 = 최고 민감도, 개인 작업 |
| 경영진 월간 대시보드 | 하이브리드 | 원천은 민감(원장) → 로컬 집계 후 요약 수치만 클라우드 게시 |
| 환율·법령 모니터링 자동화 | 클라우드 | 공개 데이터, 무인 스케줄 실행 |
| 부가세 공제 검토 | 로컬 | 거래처·금액 상세 포함, 신고 전 검토 단계 |
