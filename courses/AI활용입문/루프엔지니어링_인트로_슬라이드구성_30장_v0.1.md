## 축

**프롬프트 → 컨텍스트 → 하네스 → 루프.** 누적 관계입니다. 각 부는 **앞 부의 한계를 푸는 답**으로 등장하고, 마지막 줄에 사람의 위치가 관통합니다 — 앞 세 부는 대화 **안**, 루프는 대화 **밖**.

| 부 | 여는 질문 | 닫는 한계 → 다음 부 |
|---|---|---|
| 1 프롬프트 | 무엇을 어떻게 시킬까 | 매번 다시 써야 한다 |
| 2 컨텍스트 | AI가 무엇을 보게 할까 | 사람이 손으로 관리해야 한다 |
| 3 하네스 | 어디까지 손대게 할까 | 사람이 매번 돌려야 한다 |
| 4 루프 | 언제 멈추게 할까 | — (아우터루프가 남는다) |

### 2. 오늘 볼 네 단계 `CARDS4`

- 하단 한 줄: 뒤가 앞을 없애지 않습니다 — **쌓입니다**

### 3. "내 일은 루프를 쓰는 것이다" `QUOTE`
- 인용 원문 크게

- 한국어 번역 나란히
- 출처 **Boris Cherny** · Head of Claude Code, Anthropic · 2026년 6월

> ⚠ **직함 주의** — 국내 콘텐츠가 "안트로픽 CTO"로 옮긴 것이 돌고 있습니다. 사실이 아닙니다. Anthropic CTO는 Rahul Patil입니다. 장표에 **Head of Claude Code**로 표기.

### 4. 네 단계 지도 `MATRIX`
가로 4열 진화도. 화살표로 연결.

| | 프롬프트 | 컨텍스트 | 하네스 | 루프 |

- 맨 아랫줄만 색으로 강조. **이 강의의 척추입니다.**

### 8. 제약이 실무를 가른다 `SPLIT2`

## 제2부 · 컨텍스트 (10–15)

### 10. 부표지 `SECTION`
제2부 · 컨텍스트 / AI가 보는 전부

### 11. 컨텍스트 = AI가 보는 전부 `SPLIT2`
- 좌 **컨텍스트** — 채팅 창에 들어간 모든 것 (내가 넣은 글·파일·이미지 + AI가 참고한 내용 + 지금까지의 답변)
- 우 **컨텍스트 윈도우** — 그것을 담는 상자
- 하단 강조 **AI는 오직 이 상자 안만 보고 판단합니다.** 상자 밖은 없는 것과 같습니다
- 공감 유발 한 줄: "어제 알려줬는데 왜 또 묻지?" → 어제 대화는 다른 상자에 있었습니다

### 12. 토큰과 창 크기 `TABLE`
- 토큰 = 글을 다루는 기본 단위. 입력·출력·요금 모두 토큰
- **한글은 영어의 2~4배** ("사과" = 2~4토큰) → 우리가 상자를 더 빨리 채운다

| 모델 | 성격 | 창 크기 |
|---|---|---|
| Fable · Opus | 최고 성능 | 1M |
| Sonnet | 성능·비용 균형 | 1M |
| Haiku | 빠르고 저렴 | 200K |

- 하단: 창 크기를 정하는 건 요금제가 아니라 **어떤 모델을 쓰느냐**

### 13. 반복 압축과 정보 소실 `FLOW`
4단계 가로 도해. 상자 그림이 채워지고 압축되기를 반복.

`① 가득 참` → `② 압축 · 일부 소실` → `③ 새 대화로 다시 채움` → `④ 또 압축 · 소실 위에 소실`

- 하단 경고 **경고가 뜨지 않습니다.** 어느 순간 처음 정한 규칙을 무시하기 시작합니다
- 이 장이 2부에서 가장 반응이 좋습니다. 시간 줄이지 말 것

### 14. 컨텍스트 관리 3원칙 `CARDS3`

| 01 하나의 상자엔 하나의 주제 | 02 새 주제엔 새 상자 | 03 잔량을 본다 |
|---|---|---|
| 반찬통을 섞지 않듯 | `/clear` | `/context` |

- 하단: 상자를 관리하는 능력이 곧 **AI를 다루는 실력**

### 15. 지식 컷오프와 검색 `FLOW`
가로 타임라인.

`학습 시점` —— **지식 컷오프(모르는 구간)** —— `오늘`

- 이 구간에서 **할루시네이션**이 발생 → **검색**으로 메움
- 웹검색(즉답) vs 리서치(수 분, 인용 붙은 보고서)
- 하단: 그래도 남는 문제 — 이건 **두뇌** 쪽 통제입니다. **손발**이 생기면 다른 문제가 생깁니다 → 3부

## 제3부 · 하네스 (16–22)

### 16. 부표지 `SECTION`
제3부 · 하네스 / 손발이 생긴 AI에 고삐를 쥐여 주기

### 17. 챗봇 vs 에이전트 `SPLIT2`
- 좌 **두뇌 · 챗봇** — 요청 → 조언 → **내가 직접** 실행 (ChatGPT · claude.ai · Gemini)
- 우 **손발 · 에이전트** — 요청 → **AI가 직접** 생성·수정·삭제 (Codex · Claude Code · Antigravity)
- 중앙 축: 차이는 하나 — **직접 실행하느냐**

### 18. 손발이 생기며 나타난 리스크 `CARDS3`

| 01 할루시네이션 | 02 방향 이탈 | 03 실행 실수 |
|---|---|---|
| 없는 사실을 지어냄 | 목표·맥락을 놓침 | 되돌리기 어려운 행동 |
| 없는 조문 번호를 붙임 | 시킨 것과 다른 파일을 고침 | 삭제 · 전송 · 덮어쓰기 |

- 03 카드만 붉게 — **앞의 둘은 잘못된 결과로 끝나지만, 셋째는 되돌릴 수 없습니다**

### 19. 하네스란 무엇인가 `SPLIT2`
- 좌 **원래 뜻** — 말에 씌우는 마구. 날뛰는 말을 원하는 방향으로
- 우 **에이전트에 적용** — 빠르지만 제멋대로인 AI의 행동 범위를 **미리** 정해 둔다
- 하단 강조 하네스를 씌우면 **말을 잘 타는 사람이 아니어도** 원하는 방향으로 갈 수 있습니다
- 핵심어 강조: **"미리"** — 사고 난 뒤 고치는 게 아니라, 손대기 전에 범위를 정한다

### 20. 하네스 3대 요소 `CARDS3`
구분 기준은 **언제 작동하느냐**.

| 01 AGENTS.md | 02 스킬 | 03 MCP |
|---|---|---|
| 프로젝트 기본 지침 | 작업 수행 매뉴얼 | 외부 도구 연결 표준 |
| 채팅 시작 시 **자동** 로드 | 필요할 때만 **호출** | 바깥과 **직접 연결** |
| "항상 한국어로" | 부가세 검토 스킬 | 홈택스 · 법제처 |

### 21. AGENTS.md — 항상 켜져 있는 지침 `FLOW`
3단계 도해.

`① 채팅 시작 · 컨텍스트 윈도우 열림` → `② AGENTS.md 전체가 상자 맨 위에 얹힘` → `③ 그 지침대로 동작`

- 우측 박스 **200줄 미만으로** (Anthropic 권고)
- 길면 생기는 문제 2가지: **작업할 룸이 줄어든다** / **지침 자체가 흐려진다**
- 연결 한 줄: 9번의 "매번 다시 써야 한다"가 **여기서 해결됩니다**

### 22. 스킬과 MCP `SPLIT2`
- 좌 **스킬** = 미리 저장해 둔 상세 프롬프트
  - 호출 `/스킬이름` → `@파일` → "이걸로 만들어줘"
  - 9번의 한계 **02·03(길이·품질 편차)**이 여기서 해결
- 우 **MCP** = 외부 도구를 잇는 표준
  - AI에게 **눈과 손**을 달아 주는 일
  - 연결하는 순간 **손댈 수 있는 범위**가 정해집니다
- 하단 강조 MCP는 편의 기능이 아니라 **하네스의 일부**입니다. 무엇을 연결하느냐만큼 **무엇을 연결하지 않느냐**가 중요합니다

## 제4부 · 루프 (23–28)

### 23. 부표지 `SECTION`
제4부 · 루프 엔지니어링 / 사람이 대화 밖으로 나온다

### 24. 하네스와 루프의 차이 `MATRIX`

| | 하네스 | 루프 |
|---|---|---|
| 만드는 것 | 에이전트 **한 대**의 작업 환경 | 그것을 **반복 실행**시키는 구조 |
| 사람의 위치 | 대화 **안** — 시키고, 보고, 다시 시킨다 | 대화 **밖** — 조건만 정하고 나온다 |
| 없으면 | 제멋대로 간다 | **1회 실행**이다 |

- 하단 강조 구분 기준은 하나 — **저절로 시작되는 계기(트리거)가 있는가**

### 25. 루프의 부품 `TABLE`

| | 부품 | 하는 일 | 사무소 예 |
|---|---|---|---|
| ① | 자동화 · 트리거 | 언제 저절로 도는가 | 신고 기한 역산 알림 |
| ② | 사본 분리 | 병렬 작업이 서로 안 밟게 | 고객사별 작업 격리 |
| ③ | **스킬** | 조직 지식을 파일로 | 부가세 검토 스킬 |
| ④ | **커넥터(MCP)** | 바깥과 연결 | 홈택스 연결 |
| ⑤ | 서브에이전트 | **만든 자와 검사하는 자를 분리** | 작성 ≠ 검토 |
| ＋ | 상태 파일 | 대화 밖에 사는 기억 | 전기 확정판단 승계 |
