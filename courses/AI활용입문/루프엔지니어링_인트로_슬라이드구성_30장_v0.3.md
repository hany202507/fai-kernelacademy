# ⚠ 부표지를 떼면 생기는 문제와 대응

부표지는 장식이 아니라 **"지금 어디"**를 알리는 장치였습니다. 그냥 빼면 30장이 평평하게 흘러 청중이 위치를 잃습니다. 세 가지로 대신합니다.

| | 장치 | 내용 |
|---|---|---|
| 01 | **상단 진행 레일** | 모든 내용 장표 상단에 `제3부 하네스 · 4/9` 형식으로 부와 진행을 상주 표기 |
| 02 | **부 첫 장의 헤더 승격** | 각 부의 첫 장(`6`·`10`·`14`·`23`)만 상단 부 라벨을 **크게**. 부표지 역할을 헤더가 대신함 |
| 03 | **미니 진화도 상주** | 4번 지도의 4칸 축소판을 우측 상단에 상주시키고 **현재 부만 점등** |

03이 핵심입니다. 부표지가 없어도 "프롬프트 → 컨텍스트 → 하네스 → 루프" 중 어디인지가 매 장 보입니다. 그리고 `30`에서 완성판을 다시 띄우면 회수가 됩니다.

## 제1부 · 프롬프트 (6–9)

### 6. AI는 답을 찾지 않고 예측한다 `SPLIT2` ◀부 첫 장
- 상단 부 라벨 크게: **제1부 · 프롬프트** — 잘 시키는 법, 그리고 그 한계
- 좌 **검색엔진** — 있는 것을 찾아온다 / 우 **LLM** — 다음에 올 말을 확률로 예측한다
- 하단 강조 **같은 입력에 같은 출력이 보장되지 않습니다**
- 부연 대화에서는 문제가 아니지만, 1원이 틀리면 안 되는 업무에서는 치명적

### 7. 프롬프트 4요소 `CARDS4`

| 역할 | 맥락 | 형식 | **제약** |
|---|---|---|---|
| 누구로서 답하나 | 무엇을 놓고 하나 | 어떤 모양으로 | **무엇을 하지 마라** |
| "15년차 세무 실무자" | "3월 카드 승인 내역" | "계정·금액·적요 3열 표" | → 다음 장 |

- 앞 셋은 이미 하고 계실 것. 네 번째 카드만 강조하고 8번으로 넘김

### 8. 제약이 실무를 가른다 `SPLIT2` ⭐복원

| | 프롬프트 | 나오는 것 |
|---|---|---|
| **✗** | "3월 카드 내역 계정과목 분류해줘" | 애매한 건까지 전부 **그럴듯하게** 분류 |
| **○** | 위 + "모호한 건은 '보류'로 표시하고 **임의 분류하지 마십시오**" | 확실한 것 + **보류 큐** |

- 하단 강조 AI는 모른다고 말하기보다 **그럴듯하게 채우는 쪽**을 좋아합니다. 그러지 말라고 **명시적으로** 적어야 합니다
- 예고 한 줄 이 "보류 큐"가 4부에서 **사람에게 넘기는 경계선**으로 다시 나옵니다

### 9. 프롬프트의 한계 `CARDS3`

| 01 매번 다시 써야 한다 | 02 길어지면 앞 지시를 잊는다 | 03 사람마다 다르게 쓴다 |
|---|---|---|
| 좋은 프롬프트일수록 길다 | → 왜? 다음 부에서 | 사무소 차원의 품질 편차 |

- 02에 다음 부로 넘어가는 화살표
- 01·03은 3부(AGENTS.md·스킬)에서 해결된다고 예고

## 제2부 · 컨텍스트 (10–13)

### 10. 컨텍스트 = AI가 보는 전부 `SPLIT2` ◀부 첫 장
- 상단 부 라벨 크게: **제2부 · 컨텍스트** — AI가 보는 전부
- 좌 **컨텍스트** — 채팅 창에 들어간 모든 것 (내가 넣은 글·파일·이미지 + AI가 참고한 내용 + 지금까지의 답변)
- 우 **컨텍스트 윈도우** — 그것을 담는 상자
- 하단 강조 **AI는 오직 이 상자 안만 보고 판단합니다.** 상자 밖은 없는 것과 같습니다
- 공감 한 줄 "어제 알려줬는데 왜 또 묻지?" → 어제 대화는 다른 상자에 있었습니다

### 11. 토큰과 창 크기 `TABLE`
- 토큰 = 글을 다루는 기본 단위. 입력·출력·요금 모두 토큰
- **한글은 영어의 2~4배** ("사과" = 2~4토큰) → 우리가 상자를 더 빨리 채운다

| 모델 | 성격 | 창 크기 |
|---|---|---|
| Fable · Opus | 최고 성능 | 1M |
| Sonnet | 성능·비용 균형 | 1M |
| Haiku | 빠르고 저렴 | 200K |

- 하단 창 크기를 정하는 건 요금제가 아니라 **어떤 모델을 쓰느냐**

### 12. 반복 압축과 정보 소실 `FLOW`
`① 가득 참` → `② 압축 · 일부 소실` → `③ 새 대화로 다시 채움` → `④ 또 압축 · 소실 위에 소실`

- 하단 경고 **경고가 뜨지 않습니다.** 어느 순간 처음 정한 규칙을 무시하기 시작합니다
- 2부에서 반응이 가장 좋은 장. 시간 줄이지 말 것

### 13. 컨텍스트 관리 3원칙 `CARDS3`

| 01 하나의 상자엔 하나의 주제 | 02 새 주제엔 새 상자 | 03 잔량을 본다 |
|---|---|---|
| 반찬통을 섞지 않듯 | `/clear` · `/compact` | `/context` |

- 하단 상자를 관리하는 능력이 곧 **AI를 다루는 실력**
- 넘김 한 줄 그런데 이 관리는 **사람이 손으로** 합니다. AI가 파일을 직접 고치기 시작하면 전혀 다른 문제가 생깁니다

## 제3부 · 하네스 (14–22)

### 14. 챗봇 vs 에이전트 `SPLIT2` ◀부 첫 장
- 상단 부 라벨 크게: **제3부 · 하네스** — 손발이 생긴 AI에 고삐를 쥐여 주기
- 좌 **두뇌 · 챗봇** — 요청 → 조언 → **내가 직접** 실행 (ChatGPT · claude.ai · Gemini)
- 우 **손발 · 에이전트** — 요청 → **AI가 직접** 생성·수정·삭제 (Codex · Claude Code · Antigravity)
- 중앙 축 차이는 하나 — **직접 실행하느냐**

### 15. 손발이 생기며 나타난 리스크 `CARDS3`

| 01 할루시네이션 | 02 방향 이탈 | 03 실행 실수 |
|---|---|---|
| 없는 사실을 지어냄 | 목표·맥락을 놓침 | 되돌리기 어려운 행동 |
| 없는 조문 번호를 붙임 | 시킨 것과 다른 파일을 고침 | 삭제 · 전송 · 덮어쓰기 |

- 03만 붉게 — **앞의 둘은 잘못된 결과로 끝나지만, 셋째는 되돌릴 수 없습니다**

### 16. 두 가지 통제 — RAG와 하네스 `SPLIT2`
리스크 3종을 **어디를 겨냥해 막느냐**로 나눕니다. 이 장이 3부의 목차 역할을 합니다.

| | **RAG** — 뇌(생성)를 겨냥 | **하네스** — 손발(실행)을 겨냥 |
|---|---|---|
| 막는 것 | 01 할루시네이션 | 02 방향 이탈 · 03 실행 실수 |
| 방법 | 검증된 자료를 주고 **그 안에서만** 근거를 찾게 | 행동 범위를 **미리** 정해 둠 |

### 17. 하네스란 무엇인가 `SPLIT2` ⭐복원
- 좌 **원래 뜻** — 말에 씌우는 마구. 날뛰는 말을 원하는 방향으로
- 우 **에이전트에 적용** — 빠르지만 제멋대로인 AI의 행동 범위를 **미리** 정해 둔다

- 핵심어 **"미리"** — 사고 난 뒤 고치는 게 아니라, 손대기 전에 범위를 정합니다
- 부연 AI를 잘 다루는 사람이 되는 것보다, **잘 다뤄지게 만들어 두는** 쪽이 빠릅니다

### 20. 스킬 — 저장해 둔 매뉴얼 `SPLIT2`
- 좌 **무엇인가**
  - 상세한 프롬프트를 문서로 저장해 둔 것
  - 구조 = **본문**(작업 지시문) + **디스크립션**(설명서)
  - 새 채팅에는 **디스크립션만** 로드 → 에이전트가 "어떤 스킬이 있는지"만 알고 있다가 필요할 때 본문을 엽니다
- 우 **어떻게 쓰나**
  - 동작 **자동**(맥락 보고 알아서) / **호출**(`/스킬이름`)
  - 제작 **에이전트에게 부탁** — 시점은 **결과물이 잘 나왔을 때**
  - 주의 설명이 겹치면 **엉뚱한 스킬**이 불려 나옵니다 → description을 명확히
  - 마켓플레이스 skills.sh · k-skill
- 하단 스킬 구조는 몰라도 됩니다 — **만들기·관리·호출 모두 에이전트에게 시킵니다**
- 연결 9번의 한계 **03(품질 편차)**이 여기서 해결

### 21. MCP — 통로, 그리고 그 대가 `SPLIT2`
- 상단 도해 `AI 에이전트` → **MCP** → `Gmail · Notion · 법제처`
- 좌 **왜 붙이나 — 검색 vs 직결**

| | 연결 없이 · 웹 검색 | MCP 연결 · 법제처 |
|---|---|---|
| 경로 | AI가 인터넷을 헤맨다 | 법제처와 곧장 이어진다 |
| 정확도 | 어떤 출처를 가져올지 예측 불가 | 출처가 고정 — 높다 |
| 별표·첨부 | 자주 누락 | 그대로 가져온다 |

- 우 **대가 — 토큰**
  - 연결만 해둬도 **동작 메뉴 전체가 컨텍스트에 로드**
  - 실행할 때마다 외부와 여러 차례 주고받음
  - → **정말 필요한 몇 가지만** 연결
- 하단 강조 MCP는 편의 기능이 아니라 **하네스의 일부**입니다. 연결하는 순간 **손댈 수 있는 범위**가 정해집니다

## 제4부 · 루프 (23–28)

### 23. 하네스와 루프의 차이 `MATRIX` ◀부 첫 장
- 상단 부 라벨 크게: **제4부 · 루프 엔지니어링** — 사람이 대화 밖으로 나온다

| | 하네스 | 루프 |
|---|---|---|
| 만드는 것 | 에이전트 **한 대**의 작업 환경 | 그것을 **반복 실행**시키는 구조 |
| 사람의 위치 | 대화 **안** — 시키고, 보고, 다시 시킨다 | 대화 **밖** — 조건만 정하고 나온다 |
| 없으면 | 제멋대로 간다 | **1회 실행**이다 |

- 하단 강조 구분 기준은 하나 — **저절로 시작되는 계기(트리거)가 있는가**

### 24. 루프의 부품 `TABLE`

| | 부품 | 하는 일 | 사무소 예 |
|---|---|---|---|
| ① | 자동화 · 트리거 | 언제 저절로 도는가 | 신고 기한 역산 알림 |
| ② | 사본 분리 | 병렬 작업이 서로 안 밟게 | 고객사별 작업 격리 |
| ③ | **스킬** | 조직 지식을 파일로 | 부가세 검토 스킬 |
| ④ | **커넥터(MCP)** | 바깥과 연결 | 홈택스 연결 |
| ⑤ | 서브에이전트 | **만든 자와 검사하는 자를 분리** | 작성 ≠ 검토 |
| ＋ | 상태 파일 | 대화 밖에 사는 기억 | 전기 확정판단 승계 |

- ③④는 다른 색 — **3부에서 이미 배운 것.** "쌓인다"의 증거
- 말로 강조할 둘만: **⑤ 자기가 만든 것에는 관대하다 = 자기감사 금지** / **상태 파일 = 영원히 입사 첫날인 직원**
- 밀도 최고 장표. 나머지는 표로 넘길 것

### 25. 종료 조건 `SPLIT2`
**이 강의의 핵심 장표.**

- 상단 규칙 **제3자가 참·거짓을 판정할 수 있는 문장으로 쓴다**

| ✗ 판정할 수 없다 | ○ 판정할 수 있다 |
|---|---|
| 보고서가 좋아질 때까지 반복 | **차대 일치 + 미분류 계정 0건 + 전 수치에 원천 링크** |

- 강조 박스 **이 대목은 회계사가 개발자보다 잘합니다.** tie-out·완전성 요건이 정확히 이 형식입니다

### 26. 안전장치 4겹, 그리고 한계 `CARDS4` ⭐복원

| 1겹 | 2겹 | 3겹 | 4겹 |
|---|---|---|---|
| 검증 통과 | 최대 반복 횟수 | 시간 · 비용 한도 | 진전 없으면 중단 |

- 하단 경고 박스(크게) 형식 요건 게이트는 **"필수항목을 다 채운 틀린 보고서"**를 통과시킵니다. 조건은 **형식을 보장하지 내용을 보장하지 않습니다**
- 넘김 그래서 마지막 한 겹이 필요합니다 → 27번

### 27. 아우터루프 — 사람이 남는 자리 `NEST`
- **바깥 · 아우터루프 · 사람** — 할 가치가 있는가 / 증거가 맞는가 / 승인·차단 / **결과 책임**
- **안쪽 · 이너루프 · 에이전트** — 조사 → 구현 → 검증 → 보고 → 반복
- 하단 경고 **cognitive surrender** — 루프가 잘 돌수록 사람이 판단을 놓는다. **잘 만들수록 위험해집니다**

> ⚠ 국내 요약 다수가 아우터루프를 "사람이 안 봐도 돌아가는 자동화"로 **정반대**로 설명합니다. 원저자 정의는 **사람이 지는 책임 경계**. 이 장에서 명시적으로 짚을 것.

### 28. 모드 — 아우터루프를 쥐는 손잡이 `CARDS4`
27번이 원칙이라면 28번은 **실물**입니다.

| 매번 허락 필요 | 파일 편집은 묻지 않음 | 착수 전 계획을 브리핑 | 웹·시스템 제어까지 |
| 가장 안전 | 웹·시스템은 확인 | 큰 작업 전에 | **편하지만 위험** |

- 마지막 카드만 붉게
- 하단 **위험과 상황에 맞춰 모드를 바꿔 가며** 작업합니다
- 연결 아우터루프를 소유한다는 것은 추상적인 각오가 아니라, **지금 어느 모드에 있는지 아는 것**입니다
