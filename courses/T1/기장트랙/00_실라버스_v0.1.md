## 1. 이 과정이 푸는 문제

기장 실무자에게 AI 교육이 없어서 안 쓰는 것이 아닙니다. 도구 소개는 이미 넘칩니다. 그런데 현장에서는 세 가지가 반복해서 걸립니다.

**첫째, 챗봇으로는 기장이 안 됩니다.** LLM은 같은 입력에 다른 출력을 내는 비결정적 시스템입니다. 기장은 1원이 틀리면 안 되는 결정적 업무입니다. 이 불일치를 해소하지 않고 "AI에게 시켜본" 결과는 검토 시간을 오히려 늘립니다.

**둘째, 시연은 되는데 내 업무에는 안 옵니다.** 대부분의 회계 AI 데모는 전표 생성 장면에서 끝납니다. 그러나 기장 사무소의 실제 시간은 전표를 만든 다음이 아니라 **전표를 만들기까지의 자료 수취·분류·대사 사이클**에 쏠려 있습니다. 데모가 건드리지 않는 구간이 업무량의 다수입니다.

**셋째, 남의 회사 데이터를 다룹니다.** 기장 사무소는 고객사의 원장·통장·급여를 취급합니다. 일반 직장인 대상 AI 교육의 보안 가이드는 이 층위를 다루지 않습니다.

이 과정은 세 가지를 각각 하루씩 배정해 정면으로 다룹니다.

| 일차 | 문제 | 다루는 것 |
|---|---|---|
| **1일차** | 챗봇으로는 기장이 안 된다 | 주요 개념 — 결정론 프레임, 6블록 분해, 보안·데이터 등급 |
| **2일차** | 시연은 되는데 내 업무엔 안 온다 | 필수 활용 에이전트 — 기장 사이클 전 구간을 에이전트로 |
| **3일차** | 나 한 명 빨라져도 사무소는 그대로다 | 운영 자동화 — 사무소 단위 확산과 표준화 |

## 2. 설계 원칙 네 가지

**① 계산은 코드가, 판단은 AI가, 결정은 사람이.**
이 과정의 중심 명제입니다. 회사의 양식·계정체계·분류 규칙처럼 틀리면 안 되는 것은 AI가 **코드로 고정**하게 하고, AI 자신은 판단 후보와 근거를 제시하는 데만 씁니다. 최종 결정은 회계사가 합니다. 이 배치를 익히면 AI 산출물이 검토 부담이 아니라 검토 대상이 됩니다.

**② 검증(V)을 독립 단계로 세웁니다.**
AI가 만든 산출물을 감리하는 방법 자체를 훈련합니다. tie-out, 전기 확정분을 정답표로 삼는 채점, 이상 계정 리뷰가 별도 모듈입니다. 회계 전문가가 가르치는 AI 교육의 차별점이 여기입니다.

**③ 실습 산출물은 대화록이 아닙니다.**
모든 실습의 제출물은 **재실행 가능한 스크립트 + 산출 파일 + 검증 결과** 세 가지입니다. "AI와 이런 대화를 했다"는 산출물로 인정하지 않습니다. 다음 달에 같은 것을 다시 돌릴 수 없다면 업무가 자동화된 것이 아닙니다.

**④ 도구는 중립, 방법론이 본체입니다.**
실습은 Claude 계열 도구로 진행하되, 가르치는 것은 특정 제품 사용법이 아니라 블록 분해·지시서 설계·검증 체계입니다. 도구가 바뀌어도 남는 층만 시수에 넣었습니다.

## 3. 커리큘럼 상세

### 1일차 (4h) — 주요 개념: 기장 업무를 AI가 어디까지 하는가

#### M1. 기장 업무의 해부 — 어디에 시간이 쓰이는가 (1h)

| 구간 | 내용 |
|---|---|
| 학습목표 | 자기 업무를 6개 블록으로 분해할 수 있다 |
| 강의 | 기장 1건의 실제 공정: 자료 수취 → 분류·입력 → **대사·검토** → 신고 → 결산 → 고객 회신. 시간 배분의 실제와 자동화 데모가 다루는 구간의 격차 |
| 개념 | **6블록 문법** — R 리서치 · C 연동 · P 처리 · J 판단 · V 검증 · D 산출. 부가세 신고 1건을 R→C→P→J→V→D로 분해해 보이는 시연 |
| 실습 | 참가자가 자기 사무소의 업무 1개를 6블록으로 분해 (워크시트) |
| 산출물 | **내 업무 블록 분해도** |

> 근거: [canon/00_프레임워크/blocks/](../../../canon/00_프레임워크/blocks) 6종, [workflows/세무.md](../../../canon/00_프레임워크/workflows/세무.md)

#### M2. 결정론 프레임 — 왜 챗봇으로는 기장이 안 되는가 (1h)

| 구간 | 내용 |
|---|---|
| 학습목표 | 비결정성의 원인을 설명하고, 결정적 처리로 넘겨야 할 구간을 식별할 수 있다 |
| 강의 | LLM 원리를 재무인 관점에서. 환각·비결정성이 발생하는 지점. **AI가 잘하는 일과 절대 맡기면 안 되는 일의 경계** |
| 핵심 | 같은 원장을 두 번 넣으면 다른 시산표가 나오는 시연 → 왜 그런가 → 어떻게 막는가 |
| 개념 | **AI에게 코드를 쓰게 한다**: 분류 규칙·계산 로직을 자연어로 설명하면 AI가 결정적 스크립트로 만들어 준다. 이후 그 스크립트가 1,000건이든 10만 건이든 같은 답을 낸다 |
| 실습 | 분류 규칙 하나를 말로 설명 → AI가 코드로 고정 → 같은 데이터 3회 실행해 동일 결과 확인 |
| 산출물 | **결정적 분류 스크립트 v1 + 3회 재현 로그** |

#### M3. 남의 회사 데이터를 다루는 사무소의 보안 기준 (2h)

| 구간 | 내용 |
|---|---|
| 학습목표 | 고객 데이터의 반출 가능 여부를 즉석에서 판정하고, 사무소 기준서를 작성할 수 있다 |
| 강의 | 데이터 등급 분류 — 공개 / 사무소 내부 / **고객 위임 자료** / 개인정보(주민번호·급여). 기장 사무소가 일반 기업과 다른 지점: 위임받은 자료라 자체 판단 권한이 제한된다 |
| 드릴 | **O / X / 마스킹 3분류 드릴** — 실제 프롬프트 20건을 제시하고 즉석 판정. 오답 해설로 경계선 감각 확보 |
| 강의 | **실행환경 3종** — 로컬(내 PC·반출 없음) / 클라우드(협업·상시) / 하이브리드. 결정축 4개: 데이터 민감도 · 협업 필요성 · 상시 자동화 · 유지관리 역량 |
| 핵심 | "어디서 돌리느냐"가 곧 "데이터가 어디로 가느냐"다. 마스킹·가명처리 실습, 사업자번호·주민번호 패턴 자동 탐지 |
| 실습 | 사무소 데이터 반출 기준서 작성 (템플릿 제공) |
| 산출물 | **사무소 데이터 반출 기준서 초안 + 실행환경 결정표** |

> 이 모듈은 수강 직후 사무소에 바로 게시 가능한 문서를 남깁니다. 고객 고지·수임 계약 문구 예시를 부록으로 제공합니다.

### 2일차 (4h) — 필수 활용 에이전트: 기장 사이클을 에이전트로

> **이 날의 목표는 "만들어진 것을 구경한다"가 아니라 "내가 만든 것이 내 데이터에서 돈다"입니다.** 참가자는 자기 노트북에서 에이전트 3종을 직접 만들어 돌립니다.

#### M4. 에이전트란 무엇이고, 어떻게 만드는가 (1h)

| 구간 | 내용 |
|---|---|
| 학습목표 | 지시서·스킬·에이전트의 차이를 구분하고, 설계서로부터 에이전트를 생성할 수 있다 |
| 강의 | **성숙도 4단계**: ① 대화(챗봇에 물어본다) → ② 표준 지시서(같은 요청을 재현한다) → ③ 스킬(절차·검증을 묶어 반복 호출한다) → ④ 에이전트(스스로 도구를 쓰고 검증 루프를 돈다) |
| 개념 | **설계서를 던지면 에이전트가 만들어진다** — 무엇을 입력받고, 어떤 규칙으로 처리하고, 무엇으로 검증하고, 무엇을 산출하는지를 문서로 쓰면 도구가 실행 가능한 형태로 옮긴다 |
| 시연 | 실무에서 돌고 있는 에이전트 1종을 열어 내부 구조를 해부 — 지시서·검증 체크·산출 규격이 어떻게 생겼는지 |
| 실습 | 에이전트 설계서 1장 작성 (양식 제공: 입력 / 규칙 / 판단 보류 조건 / 검증 / 산출) |
| 산출물 | **에이전트 설계서 1종** |

#### M5. 필수 활용 에이전트 6종 — 카탈로그와 실습 3종 (1.5h)

기장 사이클 전 구간에 대응하는 에이전트 6종을 카탈로그로 제공하고, 그중 **3종을 현장에서 만들어 돌립니다**. 나머지 3종은 설계서와 함께 배포해 사무소에서 재현합니다.

| # | 에이전트 | 블록 | 하는 일 | 현장 실습 |
|---|---|---|---|---|
| 1 | **증빙 수취·정규화** | C→P | 세금계산서·카드승인·현금영수증·통장을 한 곳에 모아 표준 스키마로 정규화. 중복·누락 탐지 | ○ |
| 2 | **전표 생성** | P | 정규화된 거래에 계정과목 매핑, 분개 생성. 분류 규칙은 코드로 고정, 모호 건은 보류 큐로 | ○ |
| 3 | **레콘(대사)** | V | **통장 ↔ 전표 ↔ 세금계산서 3-way tie-out.** 차이 건만 뽑아 사유별로 분류 | ○ |
| 4 | 부가세 공제판정 | R→P→J | 매입세액 불공제 체크리스트를 전수 적용. 판정 근거 조문 첨부, 모호 건은 보류 | 설계서 배포 |
| 5 | 원천세·급여 | P→V | 근로·일용·사업(3.3%)·기타 구분, 4대보험 공제, 이행상황신고서 집계 | 설계서 배포 |
| 6 | 고객 질의 회신 | R→D | 세무 질의에 법령 원문 근거를 달아 회신 초안 작성. **근거를 못 찾으면 "확인 불가"** | 설계서 배포 |

> **3번 레콘 에이전트가 이 과정의 중심입니다.** 대부분의 회계 AI 데모가 2번에서 멈추는데, 실무 시간은 3번에 있습니다. 여기를 자동화해야 체감이 옵니다.

| 구간 | 내용 |
|---|---|
| 실습 데이터 | 가상 회사 (주)메종블룸 3개월치 — 세금계산서(매출·매입) · 카드 매입 · 통장 거래 · 거래처 마스터. **오류가 심어져 있습니다** (정산 차이, 불공제 매입, 중복 계상) |
| 실습 방식 | 1→2→3 순서로 이어 붙여 한 사이클 완주. 각 단계 산출이 다음 단계 입력이 되는 구조를 체험 |
| 산출물 | **에이전트 3종 + 레콘 결과 리포트(차이 건 사유별 분류)** |

#### M6. 검증 — AI 산출물을 감리하는 법 (1.5h)

| 구간 | 내용 |
|---|---|
| 학습목표 | AI 산출물의 정확성을 독립적으로 검증하는 체계를 설계할 수 있다 |
| 강의 | **V 블록 방법론**: tie-out(재무제표↔시산표↔원장) · 독립 재계산 · 이상 계정 리뷰 · 전기 대비 분석적 검토 |
| 핵심 | **골든셋 채점 루프** — 전기 확정 결산을 정답표로 삼아 AI 산출물을 채점 → 오분류를 규칙으로 승격 → 지시서 v2로 재실행 → 수렴. 회계사가 가진 "확정된 과거"가 최고의 학습 데이터라는 발상 |
| 드릴 | 오류를 다르게 심은 두 번째 월 데이터로 재수행 — 내가 만든 검증이 새 오류도 잡아내는가 |
| 강의 | **판단 보류의 설계** — 보류율이 낮으면 위험하고 높으면 무의미하다. 적정선을 잡는 법과 판단 로그 남기기 |
| 산출물 | **개선된 지시서 v2 + 검증 체크리스트 + 판단 로그 양식** |

### 3일차 (4h) — 운영 자동화: 나 한 명에서 사무소로

> 개인이 빨라지는 것과 사무소가 빨라지는 것은 다른 문제입니다. 이 날은 **조직 단위 확산**을 다룹니다.

#### M7. 사무소 운영 자동화 아이디어 카탈로그 (1h)

기장 사무소 운영에서 자동화 여지가 큰 구간을 카탈로그로 제시하고, 각각의 난이도·효과·선행조건을 함께 봅니다. 참가자는 자기 사무소에 해당하는 것을 골라 표시합니다.

| 영역 | 자동화 아이디어 | 난이도 |
|---|---|---|
| **자료 수취** | 고객사별 미제출 자료 자동 식별 → 요청 메시지 초안 생성 → 수취 상태 추적 | 낮음 |
| **기한 관리** | 신고 캘린더에서 담당자별 마감 역산 → 사전 알림 → 미완료 에스컬레이션 | 낮음 |
| **마감 현황** | 월 마감 진행률 대시보드 (고객사 × 단계별) — 병목이 어디서 걸리는지 보임 | 중간 |
| **품질 관리** | 신고 전 자동 점검 배치 — 전기 대비 이상 증감, 계정 오류 패턴, 누락 항목 | 중간 |
| **고객 보고** | 월간 재무 요약을 고객사별로 자동 생성 → 담당자 검토 후 발송 | 중간 |
| **지식 축적** | 판단 사례·예규 검토 결과를 사무소 라이브러리에 적립, 다음 유사 건에 자동 소환 | 중간 |
| **신입 온보딩** | 사무소 규칙을 담은 에이전트가 신입의 1차 질문을 받아냄 — 선임 시간 회수 | 높음 |

각 항목에 대해 **"이건 지금 할 수 있다 / 6개월 뒤다 / 우리 사무소엔 해당 없다"** 를 판정하는 기준을 함께 제시합니다.

#### M8. 표준 지시서 라이브러리 — 사무소의 세컨드브레인 (1.5h)

| 구간 | 내용 |
|---|---|
| 학습목표 | 개인의 개선이 사무소 전체 자산이 되는 구조를 만들 수 있다 |
| 문제 | 담당자마다 다른 지시서를 쓰면 산출물 품질이 사람에 종속된다. 담당자가 바뀌면 처음부터 다시 |
| 해법 | **지시서·검증 체크리스트·판단 로그를 라이브러리로 축적** — 폴더 체계, 명명 규칙, 버전 관리. 축적된 라이브러리를 AI가 색인하고 검색하게 하는 패턴 |
| 핵심 | **전기 판단의 승계** — 작년에 이 거래를 왜 이렇게 처리했는지가 검색되면 올해 판단이 빨라진다. 실연 |
| 실습 | 2일차에 만든 산출물을 라이브러리 구조에 배치, 색인 생성, 검색 테스트 |
| 산출물 | **사무소 블록 라이브러리 v1 (폴더 구조 + 색인)** |

#### M9. 내 사무소 적용 설계 (1h)

| 구간 | 내용 |
|---|---|
| 실습 | ① 우리 사무소 업무 10개 나열 → ② **효과 × 난이도 2×2 매핑** → ③ 첫 파일럿 1개 선정 → ④ 베이스라인 기록(이 업무에 지금 걸리는 시간·오류율) |
| 조별 | 3~4인 조별로 상호 리뷰 — 다른 사무소의 파일럿 선정을 보며 자기 선정을 재검토 |
| 핵심 | **베이스라인 없이 시작하면 효과를 증명할 수 없습니다.** 파일럿 착수 전 현재 소요시간을 반드시 기록합니다 |
| 산출물 | **사무소 업무 인벤토리 맵 + 파일럿 1건 선정서(베이스라인 포함)** |

|---|---|

| 안내 | 30일 체크인 일정 예약, 후속 과정(T2 24h) 로드맵, 커뮤니티 편입 |
| 수료 | 수료 요건 충족 확인, 수료증 및 연수학점 처리 `[협의]` |

## 4. 수료생이 가져가는 것

강의를 들었다는 기억이 아니라 **월요일에 사무소에서 돌릴 수 있는 물건**을 가져갑니다.

1. **에이전트 3종** — 증빙 정규화 · 전표 생성 · 레콘(3-way tie-out). 자기 노트북에서 만들어 돌려본 것
2. **에이전트 설계서 6종** — 위 3종 + 부가세 공제판정 · 원천세 · 고객 질의 회신
3. **사무소 데이터 반출 기준서** — 고객 고지 문구 예시 포함, 사무소에 바로 게시 가능
4. **검증 체크리스트 + 판단 로그 양식** — AI 산출물 감리용
5. **사무소 블록 라이브러리 v1** — 폴더 구조와 색인
6. **운영 자동화 아이디어 카탈로그** — 난이도·선행조건 판정 기준 포함
7. **사무소 업무 인벤토리 맵 + 파일럿 1건 선정서** (베이스라인 기록 포함)
8. **30/90일 적용 플랜** + 수료증

## 5. 평가와 수료 요건

`[협의]` 한공회 연수학점 요건에 맞춰 조정합니다. 현재 안은 다음과 같습니다.

| 요건 | 기준 |
|---|---|
| 출석 | 12시간 중 **10시간(83%) 이상** |
| 실습 제출 | 2일차 에이전트 3종 중 **2종 이상 작동 확인** |
| 최종 산출 | 3일차 **30/90일 적용 플랜 제출** |
| 지식체크 | 각 일차 말 5문항, 총 15문항 중 **10문항 이상 정답** |

> **평가는 서열이 아니라 완료 확인입니다.** 이 과정의 수료증은 "이 사람이 실무에 적용할 준비를 마쳤다"는 확인이며, 별도의 검정이나 자격을 의미하지 않습니다.

## 6. 운영 조건 — 성패가 걸린 전제

**① 1인 1노트북, 관리자 권한 필수.**
설치가 막히면 2일차 전체가 무너집니다. 사내 보안 정책상 설치가 불가능한 참가자가 있을 수 있으므로, 사전 안내와 대안 환경(웹 기반)을 준비합니다.

**② 사전 설치 체크가 별도로 필요합니다.**
개강 3~5일 전 **온라인 사전 세션 30분** `[협의]` 을 열어 설치·계정·접속을 미리 확인합니다. 이 30분이 없으면 1일차 오전이 설치 지원으로 소진됩니다.

**③ 유료 AI 구독 1종.**
무료 등급으로는 2일차 실습의 처리량을 감당하지 못합니다. 개인 구독 또는 사무소 계정 `[협의]`.

**④ 정원 35명 권장.**
2일차는 전원이 각자 노트북에서 에이전트를 만드는 시간입니다. 50명을 넘으면 보조강사 없이는 개별 대응이 불가능합니다. 정원을 늘릴 경우 보조강사 배치가 전제입니다 `[협의]`.

**⑤ 실습 데이터는 가상 회사만 사용합니다.**
참가자가 실제 고객사 데이터를 반입하는 것을 금지합니다. 사전 안내와 현장 공지 모두에 명시합니다.

## 8. 한공회 개설의 의의

**① 기존 회계 자격 교육은 전부 프로그램 조작 검정입니다.** 전산세무회계·AT·재경관리사 모두 ERP·회계 프로그램의 사용 능력을 다룹니다. AI 활용과 그 산출물의 검증을 다루는 교육은 국내 재무·회계 영역에 아직 자리가 비어 있습니다.

**② 검증을 가르칠 수 있는 곳이 회계 전문가 조직입니다.** AI 활용법은 어디서든 배울 수 있지만, AI가 만든 전표를 감리하는 방법은 회계 전문가만 가르칠 수 있습니다. 이 과정의 절반이 검증에 배정된 이유이며, 한공회가 개설 주체가 되어야 하는 이유입니다.

**③ 회원의 실질 편익이 즉시 발생합니다.** 수료생은 강의 다음 날 사무소에서 돌릴 수 있는 에이전트와 문서를 가지고 돌아갑니다. 연수학점과 실무 편익이 함께 발생하는 구조입니다.
