## 1. 이 과정이 푸는 문제

기장 실무자에게 AI 교육이 없어서 활용이 안 되는 것이 아닙니다. 도구 소개는 이미 넘칩니다. 현장에서 반복해서 걸리는 것은 세 가지입니다.

| 걸리는 지점 | 이 과정의 대응 |
|---|---|
| **챗봇으로는 기장이 안 된다** — 같은 입력에 다른 출력을 내는 시스템으로 1원이 틀리면 안 되는 업무를 할 수 없다 | 블록 1에서 결정론 프레임을 세우고, 이후 모든 블록에서 **규칙은 코드로 고정**한다 |
| **시연은 되는데 내 업무엔 안 온다** — 대부분의 회계 AI 시연은 전표 생성에서 끝나지만, 사무소의 실제 시간은 그 앞뒤의 수취·분류·대사에 쏠려 있다 | 블록 2~4에서 기장 사이클 전 구간을 에이전트로 만든다. **중심은 레콘(블록 3)** |
| **남의 회사 데이터를 다룬다** — 위임받은 자료라 자체 판단만으로 반출을 결정할 수 없다 | 블록 1에서 등급 판정 드릴을 돌리고, 사무소에 그대로 게시할 기준서를 만든다 |

## 2. 설계 원칙

**① 계산은 코드가, 판단은 AI가, 결정은 사람이.**
계정체계·분류 규칙처럼 틀리면 안 되는 것은 AI가 **결정적 코드로 고정**하게 하고, AI 자신은 판단 후보와 근거 제시에만 씁니다. 최종 결정은 회계사가 합니다.

**② 검증(V)이 독립 블록입니다.**
블록 3 전체가 검증입니다. AI 활용법은 어디서든 배울 수 있지만 AI 산출물을 감리하는 방법은 회계 전문가만 가르칠 수 있고, 이 과정이 시연형 교육과 갈리는 지점이 여기입니다.

**③ 제출물은 대화록이 아닙니다.**
모든 실습의 제출물은 **재실행 가능한 스크립트 + 산출 파일 + 검증 결과** 3종입니다. 다음 달에 같은 것을 다시 돌릴 수 없으면 자동화된 것이 아닙니다.

**④ 도구는 중립, 방법론이 본체.**
실습은 특정 도구로 진행하되 가르치는 것은 업무 분해·지시서 설계·검증 체계입니다. 도구가 바뀌어도 남는 층만 시수에 넣었습니다.

**⑤ 제작 방식 — 백지에서 만들지 않습니다.**
2시간에 에이전트를 백지에서 만드는 것은 불가능합니다. 각 에이전트는 **골격 설계서와 시드 스크립트를 배포**하고, 참가자는 ⓐ 자기 사무소 규칙을 채우고 ⓑ 실습 데이터로 실행하고 ⓒ 검증을 통과시키는 3단계를 수행합니다. 완성품을 구경하는 것도, 백지에서 헤매는 것도 아닙니다.

## 4. 블록별 상세

### B1. 기본개념 — 기장 업무를 AI가 어디까지 하는가 (2h)

**학습목표** 자기 업무를 6블록으로 분해하고, 고객 자료의 반출 가능 여부를 즉석에서 판정할 수 있다.

| 분 | 내용 |
|---|---|
| 0~20 | **기장 1건의 실제 공정** — 자료 수취 → 분류·입력 → 대사·검토 → 신고 → 결산 → 고객 회신. 시간 배분의 실제와 AI 시연이 다루는 구간의 격차 |
| 20~40 | **6블록 문법** — R 리서치 · C 연동 · P 처리 · J 판단 · V 검증 · D 산출. 부가세 신고 1건을 R→C→P→J→V→D로 분해해 보이는 시연 |
| 40~55 | 실습 — 자기 사무소 업무 1개를 6블록으로 분해 (워크시트) |
| 55~75 | **결정론 프레임** — 같은 원장을 두 번 넣으면 다른 시산표가 나오는 시연 → 원인 → 차단 방법. **AI에게 코드를 쓰게 한다**는 전환 |
| 75~90 | 실습 — 분류 규칙 하나를 말로 설명 → AI가 코드로 고정 → 같은 데이터 3회 실행해 동일 결과 확인 |
| 90~110 | **보안 — 데이터 등급 판정 드릴.** 공개 / 사무소 내부 / **고객 위임 자료** / 개인정보. 실제 프롬프트 20건 `[제작]` 을 O·X·마스킹으로 즉석 판정, 오답 해설로 경계선 감각 확보 |
| 110~120 | **실행환경 3종** — 로컬 / 클라우드 / 하이브리드. 결정축 4개(민감도·협업·상시자동화·유지관리 역량). 기준서 템플릿 배포 |

**산출물** 내 업무 블록 분해도 · 결정적 분류 스크립트 v1(3회 재현 로그) · 사무소 데이터 반출 기준서 초안
**완료 판정** 같은 입력 3회 실행에서 산출이 완전 일치할 것. 등급 드릴 20문항 중 16문항 이상 정답.

### B2. 결산 자동화 — 증빙에서 전표까지 (2h) · 에이전트 ①②

**학습목표** 흩어진 증빙을 표준 스키마로 정규화하고, 분류 규칙을 코드로 고정한 전표 생성기를 돌릴 수 있다.

| 분 | 내용 |
|---|---|
| 0~15 | **에이전트란 무엇인가** — 성숙도 4단계: 대화 → 표준 지시서 → 스킬 → 에이전트. **설계서를 던지면 에이전트가 만들어진다**는 제작 방식 |
| 15~25 | 실무에서 돌고 있는 에이전트 1종을 열어 **내부 구조 해부** — 지시서·검증 체크·산출 규격이 실제로 어떻게 생겼는지 |
| 25~65 | **에이전트 ① 증빙 수취·정규화 제작** — 세금계산서·카드승인·현금영수증·통장을 하나의 표준 스키마로. 중복·누락 탐지 |
| 65~115 | **에이전트 ② 전표 생성 제작** — 정규화 결과에 계정과목 매핑, 분개 생성. **분류 규칙은 코드로 고정하고 모호 건은 보류 큐로** |
| 115~120 | 보류율 확인과 해석 — 보류가 0이면 위험 신호 |

**에이전트 스펙**

| | ① 증빙 수취·정규화 | ② 전표 생성 |
|---|---|---|
| 입력 | 세금계산서(매출·매입) · 카드승인 · 현금영수증 · 통장 거래 | ①의 표준 거래 테이블 + 계정 매핑표 + 거래처 마스터 |
| 코드로 고정 | 스키마 정의, 날짜·금액·사업자번호 정규화, 중복 판정 키 | 계정 매핑 규칙, 부가세 구분, 차대변 균형 |
| 보류 조건 | 거래처 미식별, 금액 불일치, 기간 외 | 매핑 규칙 미해당, 계정 후보 복수, 금액 임계 초과 |
| 검증 | 건수·합계 대사(원본 ↔ 정규화), 중복 리스트 | **차대변 일치**, 전기 대비 계정별 증감 이상치 |
| 산출 | 표준 거래 테이블 + 예외 리포트 | 분개장 + 보류 큐 + 처리 로그 |

**산출물** 에이전트 ①② 작동본 · 표준 거래 테이블 · 분개장 · 보류 큐
**완료 판정** 정규화 전후 건수·합계가 일치하고, 생성된 분개장의 차대변이 0원 차이로 맞을 것.

### B3. 감사·검증 — AI 산출물을 감리한다 (2h) · 에이전트 ③

**이 과정의 중심 블록입니다.** 대부분의 회계 AI 시연이 B2에서 끝나는데, 사무소의 실제 시간은 B3에 쏠려 있습니다.

**학습목표** 3-way tie-out을 자동화하고, 전기 확정분을 정답표로 삼아 AI 산출물을 채점하는 루프를 설계할 수 있다.

| 분 | 내용 |
|---|---|
| 0~15 | **V 블록 방법론** — tie-out(재무제표↔시산표↔원장) · 독립 재계산 · 이상 계정 리뷰 · 전기 대비 분석적 검토 |
| 15~60 | **에이전트 ③ 레콘 제작** — 통장 ↔ 전표 ↔ 세금계산서 3-way tie-out. 차이 건만 뽑아 **사유별로 분류** |
| 60~80 | 심어둔 오류를 실제로 잡아내는지 확인. 잡지 못한 오류가 있으면 규칙 보강 |
| 80~105 | **골든셋 채점 루프** — 전기 확정 결산을 정답표로 AI 산출물을 채점 → 오분류를 규칙으로 승격 → 지시서 v2로 재실행 → 수렴. 회계사가 가진 "확정된 과거"가 최고의 학습 데이터라는 발상 |
| 105~120 | **드릴** — 오류를 다르게 심은 2차 데이터로 재수행. **내가 만든 검증이 처음 보는 오류도 잡는가** |

**에이전트 ③ 레콘 스펙**

| 항목 | 내용 |
|---|---|
| 입력 | 통장 거래 · 분개장(B2 산출) · 세금계산서 |
| 코드로 고정 | 매칭 키(일자 허용범위·금액 허용오차·거래처), 차이 사유 분류 규칙 |
| 보류 조건 | 다대다 매칭, 허용오차 초과, 기간 이월 추정 건 |
| 검증 | 미매칭 합계 = 3자 잔액 차이(항등식이 성립하는지), 2차 데이터 재현 |
| 산출 | 레콘 리포트(매칭/미매칭/사유별 분류) + 조치 필요 목록 |

**산출물** 에이전트 ③ 작동본 · 레콘 리포트 · 개선된 지시서 v2 · 검증 체크리스트 · 판단 로그 양식
**완료 판정** 1차 데이터에 심어둔 오류를 전부 검출하고, **2차 데이터에서 미검출 0건**일 것.

### B4. 세무 — 판정과 신고 (2h) · 에이전트 ④⑤

**학습목표** 판정 근거를 조문으로 남기는 에이전트를 만들고, 근거를 찾지 못하면 답을 지어내지 않게 설계할 수 있다.

| 분 | 내용 |
|---|---|
| 0~50 | **에이전트 ④ 부가세 공제판정 제작** — 매입세액 불공제 체크리스트를 전수 적용. **판정마다 근거 조문 첨부**, 모호 건은 보류 |
| 50~65 | 근거를 못 찾았을 때 **"확인 불가"를 반환하게 만드는 설계** — 지어내기를 구조로 차단하는 법 |
| 65~110 | **에이전트 ⑤ 원천세·급여 제작** — 근로·일용·사업(3.3%)·기타 구분, 4대보험 공제, 이행상황신고서 집계 |
| 110~120 | 두 에이전트의 산출을 B3의 검증 체계에 물려 재확인 |

**에이전트 스펙**

| | ④ 부가세 공제판정 | ⑤ 원천세·급여 |
|---|---|---|
| 입력 | 매입 세금계산서·카드 매입(B1 정규화 결과) | 인사 마스터 · 지급 기록 |
| 코드로 고정 | 불공제 유형 체크리스트, 사업자 상태 확인 절차 | 소득 구분 판정 규칙, 세율·공제 계산 |
| 보류 조건 | 접대성·비업무용 판단 필요, 겸영 안분 대상 | 소득 구분 불명, 비거주자, 중도 입퇴사 |
| 검증 | 공제·불공제 합계 = 매입세액 총계, 판정별 근거 첨부율 100% | 급여대장 ↔ 이행상황신고서 3-way tie-out |
| 산출 | 공제판정표(근거 조문 포함) + 보류 큐 | 급여대장 + 이행상황신고서 집계 + 정보요청 목록 |

**산출물** 에이전트 ④⑤ 작동본 · 공제판정표 · 이행상황신고서 집계
**완료 판정** 모든 판정에 근거가 붙어 있고, 근거 없는 건은 "확인 불가"로 분류돼 있을 것. 급여대장과 신고서 집계가 0원 차이로 일치할 것.

### B5. 기장 운영 효율화 — 나 한 명에서 사무소로 (2h)

개인이 빨라지는 것과 사무소가 빨라지는 것은 다른 문제입니다. 이 블록은 **조직 단위 확산**을 다룹니다.

**학습목표** 개인의 개선이 사무소 자산으로 축적되는 구조를 만들 수 있다.

| 분 | 내용 |
|---|---|
| 0~40 | **운영 자동화 카탈로그** — 영역별 아이디어와 난이도·선행조건. 참가자는 자기 사무소 해당분을 표시 |
| 40~90 | **표준 지시서 라이브러리 구축** — 앞 블록 산출물을 폴더 체계·명명 규칙·버전 관리에 배치, 색인 생성, 검색 테스트 |
| 90~110 | **전기 판단의 승계** — 작년에 이 거래를 왜 이렇게 처리했는지가 검색되면 올해 판단이 빨라진다. 실연 |
| 110~120 | 담당자 교체 시나리오 — 라이브러리만 넘겨서 동일 산출이 나오는가 |

**운영 자동화 카탈로그**

| 영역 | 아이디어 | 난이도 |
|---|---|---|
| 자료 수취 | 고객사별 미제출 자료 자동 식별 → 요청 메시지 초안 → 수취 상태 추적 | 낮음 |
| 기한 관리 | 신고 캘린더에서 담당자별 마감 역산 → 사전 알림 → 미완료 에스컬레이션 | 낮음 |
| 마감 현황 | 월 마감 진행률 대시보드(고객사 × 단계) — 병목 가시화 | 중간 |
| 품질 관리 | 신고 전 자동 점검 — 전기 대비 이상 증감, 계정 오류 패턴, 누락 항목 | 중간 |
| 고객 보고 | 월간 재무 요약 고객사별 자동 생성 → 담당자 검토 후 발송 | 중간 |
| 지식 축적 | 판단 사례·예규 검토 결과를 라이브러리에 적립, 유사 건에 자동 소환 | 중간 |
| 신입 온보딩 | 사무소 규칙 에이전트가 신입의 1차 질문을 받아냄 — 선임 시간 회수 | 높음 |

각 항목에 **"지금 할 수 있다 / 6개월 뒤다 / 우리 사무소엔 해당 없다"** 를 판정하는 기준을 함께 제시합니다.

**산출물** 사무소 블록 라이브러리 v1(폴더 구조 + 색인) · 운영 자동화 판정표
**완료 판정** 라이브러리 색인에서 특정 판단 근거를 30초 안에 찾아낼 것.

> 근거: [workflows/내부통제.md](../../../canon/00_프레임워크/workflows/내부통제.md) · [workflows/보고.md](../../../canon/00_프레임워크/workflows/보고.md)

### B6. 적용 설계·수료 (2h)

| 분 | 내용 |
|---|---|
| 0~40 | **사무소 업무 인벤토리** — 업무 10개 나열 → **효과 × 난이도 2×2 매핑** |
| 40~60 | **파일럿 1건 선정 + 베이스라인 기록** — 이 업무에 지금 걸리는 시간과 오류율. 베이스라인 없이 시작하면 효과를 증명할 수 없습니다 |

## 8. 운영 조건 — 성패가 걸린 전제

**① 1인 1노트북, 관리자 권한 필수.** 설치가 막히면 B2 전체가 무너집니다. 사내 보안 정책상 설치가 불가능한 참가자를 위한 대안 환경(웹 기반)을 준비합니다.

**② 사전 온라인 세션 30분** `[협의]` — 개강 3~5일 전 설치·계정·접속 점검. 이 30분이 없으면 1일차 오전이 설치 지원으로 소진됩니다.

**③ 유료 AI 구독 1종.** 무료 등급으로는 B2~B4의 처리량을 감당하지 못합니다. 개인 구독 / 사무소 계정 / 제공 계정 중 부담 주체 `[협의]`.

**④ 정원 30명.** B2~B4는 전원이 각자 노트북에서 에이전트를 만드는 시간입니다. 초과 시 보조강사 배치가 전제입니다 `[협의]`.

> 참고 — 서울지방세무사회는 2026년 7월 29~30일 AI 실습교육(2일·1일 7시간)에 **실습 보조교사 4명**을 배치했습니다. 실습형 편성에는 인당 지원이 필요하다는 선례입니다. (한국세정신문 2026.7.9, 확인일 2026-07-29)

**⑤ 장소·장비.** 30명 동시 접속 기준의 전원과 와이파이 대역폭 `[협의]`.

| | v0.1 | v0.2 |

**개정 사유 세 가지.**
첫째, v0.1은 "무엇을 다룬다"까지만 적혀 있고 **분 단위 진행과 통과 기준이 없어** 강사 교체나 위원 검토가 불가능했습니다. 둘째, 6종 카탈로그 중 3종만 만들고 3종은 배포한다는 구성은 **수료생이 손에 쥐는 것을 흐리게** 했습니다. 셋째, 검증이 하나의 모듈(M6)에 묶여 있어 이 과정의 차별점이 구조상 드러나지 않았습니다.
