# kernel-html-reports

입력 자료를 **읽는 보고서 형식의 단일 파일 HTML + PDF** 로 만든다.
디자인은 `assets/template.html` 에 박제돼 있다. 완성형은 `reference/기준_보고서.html` — **막히면 그것을 편다.**

자매 스킬 `kernel-html-slides` 와 같은 토큰을 쓴다(`assets/theme.md`).
**문체도 같다** — 정본은 `../kernel-html-slides/assets/tone.md`. 제목·소제목·콜아웃을 쓰기 전에 본다.

## 절대 원칙

1. **디자인을 발명하지 않는다.** 색·간격·컴포넌트는 템플릿 CSS 만 쓴다. 새 클래스·색 리터럴을 만들지 않는다.
2. **단일 파일.** 외부 리소스는 Pretendard 폰트 CDN 하나뿐.
3. **이모지 미사용.** 라벨·강조는 텍스트와 색으로만.
4. **내용을 지어내지 않는다.** 숫자·인용·출처는 입력 자료에서만. 근거가 없으면 그 항목을 빼거나, 자료에 없다고 본문에 밝힌다.
5. **자료를 통째로 옮기지 않되, 빠뜨리지도 않는다.** 표는 원문 목록의 *요약*이지 *대체*가 아니다. 지면 때문에 뺀 것이 있으면 **무엇을 왜 뺐는지 사용자에게 알린다.**
6. **보고서는 주장을 가진다.** 요점 나열이 아니라 "무엇을 발견했고 그래서 무엇을 해야 하는가"가 드러나야 한다. 자료에 결론이 없으면 **묻는다.**
7. **최종 형태는 A4 인쇄물이다.** 화면에서 예뻐도 장이 뒤엉키거나 표가 잘리면 실패다. 완성 전에 `printcheck.ps1` 로 실측한다.
8. **한 요소의 색은 한 곳에서만 드러낸다.** 장의 색은 고스트 번호가, 지표의 색은 숫자가 진다. 겹치면 화려해지는 게 아니라 **위계가 무너진다.**
9. **문장도 발명하지 않는다.** 제목·소제목·콜아웃은 사실을 담는다(숫자 → 벌어진 일 → 명사구). 대구·격언·과장은 `tone.md` 진단표로 걷어낸다. 원본 자료의 문장은 사용자 문장이니 다시 쓰지 않는다.

## 지면 우선순위 — 충돌하면 아래를 포기한다

| 순위 | 기준 | 규칙 | 어긋나면 |
|---|---|---|---|
| **1** | **장** | `h2` 하나 = **반드시** 새 페이지에서 시작 | **깨지 않는다.** 아래를 대신 포기한다 |
| 2 | **덩어리** | 「소제목 + 도입 문단 + 그림 + 주석」은 갈라지지 않는다 | 그림을 줄인다 |
| 3 | **그림** | 표·카드·지표·단계·정의목록·콜아웃·인용·목록은 통째로 한 페이지 | 항목 수를 줄이거나 블록을 나눈다 |
| 4 | **주석** | 표·그림과 같은 페이지. `.figw` 로 감싼다 | 감싸지 않으면 떨어진다 |
| 5 | **위계 여백** | 사다리는 고정값 | 줄이지 말고 `--pgap` 을 낮춘다 |
| **6** | **채움** | 각 페이지 55~99% | `--pgap` → `--pfs` 순. **여기서 안 되면 남는 공백을 받아들인다** |

**채움률은 가장 낮은 기준이다.** 장 경계를 옮기거나 위계 여백을 줄이거나 내용을 덜어내서 채움률을 맞추면 **그건 통과가 아니라 실패다.**

**`class="sec cont"` 를 채움률 대책으로 쓰지 않는다.** 유일한 용도는 작성자가 긴 장 하나를 두 `.sec` 로 쪼개 놓고 인쇄에서 한 장으로 보이게 할 때뿐이다(뒤쪽 `.sec` 에는 장 머리를 다시 넣지 않는다).

## 절차

### 1. 입력과 결론 확보
자료를 확인한다. **자료에서 안 나오면 쓰기 전에 묻는다** — 결론/권고, 독자, 작성자·일자. 제목·장 구성은 자료에서 추론한다.

### 2. 구조 설계 (쓰기 전에)
뼈대: 표지(`.rhead`) → 핵심 요약(`.summary`) → 장(`.sec`) 여러 개 → 결론 장 → 푸터(`.foot`).

**장을 몇 개로 나눌지는 자료가 정한다.** 정해진 개수는 없다. 유일한 제약은 **장 하나가 A4 반 페이지 이상을 채워야 한다**는 것 — 장은 반드시 새 페이지에서 시작하므로 짧은 장은 남은 지면을 그대로 버린다. 자료가 12개 장으로 자연스럽게 나뉘고 각 장이 한 페이지를 넘으면 **12개로 간다.** 억지로 8개로 묶으면 장 안이 `h3` 만으로 눌려 도리어 읽기 나빠진다.

장이 짧을 수밖에 없으면 둘 중 하나다 — ① **`h2` 자체를 합쳐** 상위 장으로 묶는다(원래 장들은 `h3` 가 된다), ② 자투리를 받아들이고 사용자에게 알린다. **`sec cont` 로 페이지 나눔만 끄는 선택지는 없다.**

내용 성격에 맞는 컴포넌트를 고른다 → `assets/components.md`.

| 내용 | 컴포넌트 |
|---|---|
| 설명·논증 | `<p>` + `h3` |
| 근거 나열 / 순서 있는 목록 | `pts` / `nums` |
| 수치 비교 | `tw` + table |
| 핵심 수치 2~3개 | `stats` |
| 병렬 개념·대안 | `cards` |
| 절차·일정 | `steps` |
| 용어 정의 | `kv` |
| 전제·주의·리스크 | `callout` (경고는 `risk` 색) |
| 인용 / 명령어 | `quote` / `code` |
| 한 문장 결론 | `banner` |

**위계는 문서 전체에서 하나여야 한다.** 모든 `.sec` 는 `.no` → `h2` → `.lead` 를 빠짐없이 갖고, `.sech` 에는 `data-n="01"` 을 준다(고스트 번호). `.card .idx` 형식은 한 가지로 고정하고 섞지 않는다. 같은 성격의 내용은 같은 컴포넌트로 — 설계 단계에서 매핑을 정하고 끝까지 지킨다.

분량이 크면 설계안(장 제목 + 컴포넌트)을 먼저 보여주고 진행한다.

### 3. 채우기
- `assets/template.html` 을 산출 파일로 복사(예: `<주제>_보고서.html`).
- **예시 장 블록을 전부 지우고** 설계한 장으로 `<main class="doc">` 를 채운다.
- 마크업은 `assets/components.md` 에서 복사해 내용만 바꾼다.
- `{{...}}` 를 전부 치환한다.
- 각 `.sec` 에 `id` 와 **`data-toc="장 제목"`** 을 준다 → **목차는 JS 가 자동 생성한다. 손으로 쓰지 않는다.**
- 장 순서대로 `--c/--ct/--bgc` 를 `a1 → a2 → a3` 순환. 리스크 장은 `risk`.
- `.summary` 는 본문을 다 쓴 뒤 마지막에 채운다.

### 4. 실측
```
powershell -ExecutionPolicy Bypass -File <스킬>/assets/printcheck.ps1 "<C:\절대\경로\보고서.html>"
```
페이지 수·채움률·배치 결함(소제목 고아, 주석 분리)을 찍는다.

- **배치 결함을 먼저 없앤다.** 템플릿 규칙이 살아 있으면 원래 나오지 않는다. 나온다면 덩어리가 한 페이지보다 커서 브라우저가 규칙을 포기한 것 → **그림을 줄인다.**
- **채움은 `--pgap` → `--pfs` → 원문 근거가 있는 분량 보강** 순으로. 이 스킨의 `--pgap` 정상 범위는 **1.0~1.15** 다.
- 허용된 수단을 다 쓰고도 남으면 **거기서 멈추고 사용자에게 보고한다.**

> **이 스크립트는 채움률만 본다.** 장이 새 페이지에서 시작하는지는 검사하지 않으므로 `sec cont` 로 장 경계를 없애면 '통과' 가 찍힌다 — **그 통과는 가짜다.**
> **`opacity` 를 쓰면 페이지가 0쪽으로 보고된다.** 오류가 아니라 조용한 0이라 놓치기 쉽다. 자세한 것은 `reference/layout.md` 5절.

세부 규칙(간격 사다리, 인쇄 CSS 해설, 덩어리 크기 상한, 손잡이 범위)은 **`reference/layout.md`** 에 있다. 평소에는 읽지 않아도 된다.

### 5. PDF 동봉 (필수)
**HTML만 주고 "인쇄해서 쓰세요" 라고 하지 않는다.** 브라우저 인쇄는 여백에 날짜·제목·`file:///` 주소를 덧찍는데 그건 **CSS 로 끌 수 없다**(브라우저가 그린다). 헤드리스 인쇄에는 애초에 없다.

```
powershell -ExecutionPolicy Bypass -File <스킬>/assets/printcheck.ps1 "<C:\절대\경로\보고서.html>" -Pdf "<C:\절대\경로\보고서.pdf>"
```

- **경로는 반드시 절대경로.** 상대경로를 주면 헤드리스가 자기 작업 디렉터리 기준으로 풀어 엉뚱한 곳에 쓰려다 실패한다.
- **PDF 뷰어가 그 파일을 열어 두면 덮어쓰기가 실패한다.** 사용자에게 닫아 달라고 요청한다 — 다른 이름으로 우회 저장하지 않는다(어느 쪽이 최신인지 알 수 없게 된다).
- 사용자가 "인쇄하면 날짜·제목이 계속 찍힌다" 고 하면 **문서를 고치려 들지 않는다.** ① 동봉한 PDF 를 쓰라고 안내, ② 굳이 브라우저로 뽑겠다면 '옵션 더보기 → 머리글 및 바닥글' 해제를 안내한다.

### 6. 검증 (필수)

- [ ] 브라우저에서 좌측 목차가 **모든 장을 자동으로** 표시하고 클릭 이동·하이라이트가 동작하는가
- [ ] `grep 'sec cont'` 결과가 **비어 있는가**(의도적으로 쓴 경우가 아니라면 하나도 없어야 한다)
- [ ] 장 수 = 새 페이지에서 시작하는 페이지 수인가
- [ ] `printcheck` 판정이 **통과**인가. 아니어도 허용된 수단을 다 썼다면 그대로 두고 보고한다 — **장 경계를 깨서 통과시키지 않는다**
- [ ] **PDF 를 HTML 과 같은 폴더에 함께 만들었는가**
- [ ] 인쇄 미리보기에서 표·카드·콜아웃·`steps` 가 페이지 경계에서 잘리지 않는가. 목차·버튼은 사라져야 한다
- [ ] 모든 `.sech` 에 `data-n` 이 있는가(없으면 그 장만 고스트 번호가 빈다)
- [ ] 위계가 전 장에서 같은가(`.no`/`h2`/`.lead` 3종, `idx` 형식 통일, 같은 성격=같은 컴포넌트)
- [ ] `opacity`·그라데이션 텍스트·색 리터럴을 새로 만들지 않았는가
- [ ] 미치환 `{{...}}`·오타·깨진 태그가 없는가
- [ ] 표의 수치·인용·출처가 입력 자료와 일치하는가
- [ ] **원문 목차와 1:1 로 대조했는가**(원칙 5). 표로 바꾼 목록과 문단으로 합친 절에서 항목이 통째로 증발하기 쉽다

## 산출물 안내

파일 경로(**HTML·PDF 둘 다**), 장 구성과 분량, 여는 법, 인쇄 결과(총 몇 쪽), 그리고 **자료에서 의도적으로 뺀 것이 있으면 무엇을 왜 뺐는지**를 짧게 알린다.
